Building a Sale Price Calculator, test first

This page follows one small project from start to finish: an AI agent builds a web page, and you guide it by saying what "correct" means. You don't write any code. You'll see what we're building, the rules it has to follow, and every step of the process.

To build it yourself, make your own copy of the template repo prism-lca/tdd-sale-calculator and follow its README.

What we're building

A one-page website called index.html that works out sale prices. A shopper or a store clerk types in the price and the discount, and the page shows what the item costs. Here's the finished page, working. Try it:

The page has two parts, and the agent writes both:

The screen

The boxes you type into and the price you see. You check this part yourself by using it.

The calculation

The rules that turn a price and discounts into a sale price. This is the part the tests check, because a wrong price is the mistake that matters.

The rules it has to follow

Before anything gets built, we write down what "correct" means as examples with real answers. Anyone can check these on a phone calculator. Each one will become a test.

#ExampleCorrect answerWhy it's here
1$50 with 20% off$40.00The basic case
2$19.99 with 15% off$16.99The raw math gives $16.9915. Prices need whole cents.
3A discount of 120%An error messageA store can't pay you to take an item

What's a test? An answer key, written first

Imagine grading homework. Before anyone does it, you write the answer key: "Question 1: $40.00." Then you grade a blank sheet. It should be marked wrong, which proves your key can catch a mistake. Only then does someone do the homework, and you grade it again.

A test is that answer key, and the computer grades against it automatically. Red means "wrong answer." Green means "matches the key." The rule of test-first work: every rule shows red before it shows green.

Below is what happened at each step when an agent built this calculator. The results shown are from a real run.

Step 1 · You

Ask for it, with the rules

In your copy of the template, create issue #1 from the Sale Price Calculator issue template. It already holds the three rules from the table above. Then start your agent in the codespace and say:

You say

Let's work on issue #1, following AGENTS.md.

The repo's AGENTS.md tells the agent the test-first steps, so you don't have to spell them out.

Step 2 · Agent and you

Agree on the checks

A good agent doesn't start building straight away. It reads the rules back and asks about anything unclear.

Agent says

I'll write three checks, one per rule. Two questions first. For rounding, should $16.9915 round to the nearest cent ($16.99), or always round down? And is a discount of exactly 100% (free) allowed?

Your job: answer these. They're questions about how the store works, not about code, and the agent shouldn't guess. Settling them now is the most useful step in the whole process. The agent updates the issue so the rules always match what you decided.

Step 3 · Rule 1

$50 with 20% off → $40.00

The agent writes the check for rule 1 before the calculation exists, and runs it. Then it writes just enough to pass, and runs it again. It commits the test before the code, so the history shows the test came first.

First run: before the calculation
  • Fail20% off $50 is $40.00Expected 40, got 0
After the agent adds the calculation
  • Pass20% off $50 is $40.00

What this means: the red run proves the check can catch a wrong answer (0 isn't 40). The green run proves the calculation now gets it right.

Step 4 · Rule 2

$19.99 with 15% off → $16.99

First run
  • Pass20% off $50 is $40.00
  • Fail15% off $19.99 is $16.99Expected 16.99, got 16.9915
After the agent adds rounding
  • Pass20% off $50 is $40.00
  • Pass15% off $19.99 is $16.99

What this means: the calculation did the math right but didn't round to whole cents. The check caught a bug nobody would have noticed until a customer saw "$16.9915" on the screen.

Step 5 · Rule 3

A discount over 100% → a clear error

First run
  • PassRules 1 and 2
  • FailA 120% discount gives a clear errorExpected an error, but it gave a price instead
After the agent adds the error
  • PassRules 1 and 2
  • PassA 120% discount gives a clear error

What this means: before the fix, 120% off $50 came out as a price of −$10.00. Now it shows "A discount can't be more than 100%". Every run re-checks the earlier rules too, so this fix didn't break rules 1 or 2.

Step 6 · Agent

Build the screen

With all three rules green, the agent builds the screen: the price and discount boxes, and the receipt that shows the result. It connects them to the calculation that just passed every check. That's the page at the top of this guide. It starts a web server so you can open the page from the codespace.

Why this order: the calculation is where a mistake costs money, so it's proven first. The screen is easy to check by eye, so you check it yourself in step 7.

Step 7 · You

Try it yourself

Open index.html and use it like a shopper would. Try it with the calculator at the top of this page:

  • Put in $50 and 20%, and check you get $40.00.
  • Put in $19.99 and 15%, and check you get $16.99.
  • Type 120 as the discount, and check you see the error message.
  • Try a price from a real receipt of your own.

Why this still matters: the tests only check the calculation. Your own check catches what they can't, such as a box that's mislabeled or a result that's hard to read. When you're done, the agent asks how you checked it, posts the final test results on issue #1, and closes it.

What to watch for

  • GoodEvery rule shows red before it shows green.
  • GoodFailure messages mention your numbers, like "expected 40, got 0".
  • GoodEvery run re-checks all the earlier rules, not just the newest.
  • StopThe agent built something before showing you a failing check.
  • StopThe agent changed a rule or an expected answer to make it pass, without asking you.
  • StopThe agent says "all tests pass" but didn't show you the results.
