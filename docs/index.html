Build a Sale Price Calculator, test first

You'll guide an AI coding agent to build a small web page. You don't write any code or tests. You decide what "correct" means, the agent proves it, and you check the result yourself.

This page explains how it works, then walks you through the activity step by step. The project lives in the template repo prism-lca/tdd-sale-calculator.

The one rule: before the agent writes any code, it has to show you a test that fails. Then it writes the code that makes that test pass.

What you're building

A one-page website called index.html that works out sale prices. You type in a price and a discount, and the page shows the sale price and how much you save. Here's the finished page, working. Try it:

The page has two parts, and the agent writes both:

The screen

The boxes you type into and the price you see. You check this part yourself by using it.

The calculation (sale.js)

The rules that turn a price and a discount into a sale price. This is the part the automated tests check, because a wrong price is the mistake that matters.

The rules it has to follow

Before anything gets built, we write down what "correct" means. These three rules are the whole specification: each is an example with a real answer, anyone can check on a phone calculator, and each one becomes a test.

#ExampleCorrect answer
1$50 with 20% off$40.00
2$19.99 with 15% off$16.99 (rounded to the nearest cent)
3A discount over 100%, for example 120%The message "A discount can't be more than 100%"

What's a test? An answer key, written first

Imagine grading homework. Before anyone does it, you write the answer key: "Question 1: $40.00." Then you grade a blank sheet. It should be marked wrong, which proves your key can catch a mistake. Only then does someone do the homework, and you grade it again.

A test is that answer key, and the computer grades against it automatically. Red means "wrong answer." Green means "matches the key." The rule of test-first work: every rule shows red before it shows green.

Why work this way

AI agents write code fast, and they're confident even when they're wrong. Watching a test fail first proves it can tell broken code from working code. When it passes afterwards, you know the code does what you asked. This is called test-driven development, or TDD.

Who does what

You

  • Give the agent the rules
  • Answer its questions, and agree on the rules before any code
  • Watch for a red (failing) run before each green (passing) one
  • Check the finished page by hand

The agent

  • Turns your rules into tests, and explains each one
  • Writes the code
  • Runs the tests and shows you the results
  • Saves (commits) and pushes your work once, at the end

The agent follows the steps in the repo's AGENTS.md file. Claude Code, Codex and OpenCode all read it, so you don't have to explain the process to the agent. Everything happens on main: there are no issues, branches or pull requests.

Directions

  1. 1
    You

    Make your own copy

    Go to the template repo and click Use this template → Create a new repository.

    • Owner: choose prism-lca, not your own account, so your teacher can see your work.
    • Repository name: tdd-sale-calculator-<your-name>, for example tdd-sale-calculator-diana.

    Then click Create repository.

  2. 2
    You

    Open it in a codespace

    In your new repo, click Code → Codespaces → Create codespace on main. The agents are already installed. Start one in the terminal: claude, codex or opencode. The first time, it asks you to sign in.

  3. 3
    You

    Give the agent the rules

    Copy this message and paste it to your agent:

    The rules

    Let's build the Sale Price Calculator, following AGENTS.md. Here are the rules: 1. $50 with 20% off → $40.00 2. $19.99 with 15% off → $16.99 (rounded to the nearest cent) 3. A discount over 100% → no price, and the message "A discount can't be more than 100%"

    The rules aren't saved in the repo. The tests the agent writes become the record of them.

  4. 4
    Agent asks · you decide

    Agree on the rules

    A good agent doesn't start building straight away. It reads the rules back and asks about anything unclear, for example:

    Agent says

    Two questions first. For rounding, should $16.9915 round to the nearest cent ($16.99), or always round down? And is a discount of exactly 100% (free) allowed?

    Your job: answer these. They're questions about how the store works, not about code, and the agent shouldn't guess. You can add rules of your own too. Whenever you change a rule, the agent shows you the full updated list. No code gets written until you say the list is right. Settling these questions now is the most useful step in the whole process.

  5. 5
    Agent · you watch

    Red, then green, one rule at a time

    For each rule, the agent repeats this loop:

    1 · REDWrite one test. Run it. It fails, because the code doesn't exist yet.
    2 · GREENWrite just enough code to pass it. Run all the tests. They pass.
    3 · TIDYClean up the code. Every test still passes.

    After every test run, red or green, the agent stops and asks you whether to go on. Look at the result, then tell it to proceed.

    Here's what you'll see for each rule. These results are from a real run.

    Rule 1: $50 with 20% off → $40.00

    Red: before the calculation
    • Fail20% off $50 is $40.00Expected 40, got 0
    Green: after the agent adds it
    • Pass20% off $50 is $40.00

    What this means: the red run proves the test can catch a wrong answer (0 isn't 40). The green run proves the calculation now gets it right.

    Rule 2: $19.99 with 15% off → $16.99

    Red
    • Pass20% off $50 is $40.00
    • Fail15% off $19.99 is $16.99Expected 16.99, got 16.9915
    Green: after the agent adds rounding
    • Pass20% off $50 is $40.00
    • Pass15% off $19.99 is $16.99

    What this means: the math was right but didn't round to whole cents. The test caught a bug nobody would have noticed until a customer saw "$16.9915" on the screen.

    Rule 3: a discount over 100% → a clear error

    Red
    • PassRules 1 and 2
    • FailA 120% discount gives a clear errorExpected an error, but it gave a price instead
    Green: after the agent adds the error
    • PassRules 1 and 2
    • PassA 120% discount gives a clear error

    What this means: before the fix, 120% off $50 came out as a price of −$10.00. Every run re-checks the earlier rules too, so this fix didn't break rules 1 or 2.

    You watch every test fail before its code is written, so you can see each test came first. The agent is never allowed to weaken or delete a test to make it pass. If a test looks wrong, it has to stop and ask you.

  6. 6
    Agent builds · you check

    Build the page and try it yourself

    With every rule green, the agent builds the screen and connects it to the tested calculation. It starts a web server so you can open the page from the codespace. Use it like a shopper would:

    • Put in $50 and 20%, and check you get $40.00.
    • Put in $19.99 and 15%, and check you get $16.99.
    • Type 120 as the discount, and check you see the error message.
    • Try a price from a real receipt of your own.

    Why this still matters: the tests only check the calculation. Your own check catches what they can't, such as a box that's mislabeled or a result that's hard to read.

  7. 7
    Agent · you describe your check

    Wrap up

    The agent asks how you checked the page, then shows you a final run of all the tests. Then it saves (commits) everything and pushes it to your repo. The tests in sale.test.js are the record of what you agreed: each one is named after one of your rules.

Other things you can say to the agent

Understanding a test

Explain in plain English what each test checks, and how it could still pass while the code is broken.

Checking the tests

Run all the tests again and show me, in plain English, which rules pass and which fail.

What to watch for

  • GoodEvery rule shows red before it shows green.
  • GoodFailure messages mention your numbers, like "expected 40, got 0".
  • GoodEvery run re-checks all the earlier rules, not just the newest.
  • StopThe agent built something before showing you a failing test.
  • StopThe agent changed a rule or an expected answer to make it pass, without asking you.
  • StopThe agent says "all tests pass" but didn't show you the results.
  • StopThe agent built things none of your rules asked for.

If you see a stop sign, say: "Stop. Go back and follow the test-first steps in AGENTS.md."
