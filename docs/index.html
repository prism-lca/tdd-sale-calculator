PRISM · tdd-sale-calculator · how it works

Building with an AI agent, test first

You don't need to write code or tests. You decide what "working" means, the agent proves it, and you check the result yourself.

New to this? Read the worked example, which follows an agent building a Sale Price Calculator web page from start to finish.

The project lives in the template repo prism-lca/tdd-sale-calculator. Each student makes their own copy and works through it with an agent.

The one rule: before the agent writes any code, it has to show you a test that fails. Then it writes the code that makes that test pass.

Why work this way

AI agents write code fast, and they're confident even when they're wrong. A test is a small program that checks one thing the code should do, and it gives a yes-or-no answer. Watching a test fail first proves it can tell broken code from working code. When it passes afterwards, you know the code does what you asked. This is called test-driven development, or TDD.

Who does what

You

  • Describe what should happen, with real examples
  • Answer the agent's questions
  • Agree on the rules before any code is written
  • Watch for a red (failing) run before each green (passing) one
  • Check the finished work by hand

The agent

  • Turns your examples into tests
  • Writes the code
  • Runs the tests and shows you the results
  • Explains each test in plain English
  • Handles git: commits each test, then the code, and keeps the issue up to date

The six steps

This is the process in the repo's AGENTS.md. Claude Code, Codex and OpenCode all read that file, so the agent already knows it. Everything happens on main: no branches, plan files or pull requests.

  1. 1
    You

    Make your copy and open it

    On the template repo, click Use this template → Create a new repository. Set Owner to prism-lca (not your own account) and name it tdd-sale-calculator-<your-name>. Then click Code → Codespaces → Create codespace on main, and start an agent in the terminal: claude, codex or opencode.

  2. 2
    You

    Create the issue, with examples

    Go to Issues → New issue → Sale Price Calculator and click Create. It becomes issue #1. The rules are already filled in as examples anyone can check yes or no, with real numbers:

    Scenario: Simple discount Given an item costs $50 When I take 20% off Then the sale price is $40.00 Scenario: Round to the cent Given an item costs $19.99 When I take 15% off Then the sale price is $16.99
  3. 3
    Agent asks · you decide

    Agree on the rules

    Tell the agent: "Let's work on issue #1, following AGENTS.md." It shows you the rules and asks about anything unclear, for example: "Should $16.9915 round to the nearest cent, or always round down?" or "Is a 100% discount allowed?" Answer carefully, and add rules of your own if you like. The agent updates the issue so it always matches what you decided. Settling these questions before any code exists is the most useful part of the process. No code gets written until you say the list is right.

  4. 4
    Agent · you watch

    Test, then build, one rule at a time

    For each rule on the issue, the agent repeats this loop:

    1 · REDWrite one test. Run it. It fails, because the code doesn't exist yet.
    2 · GREENWrite just enough code to pass it. Run all the tests. They pass.
    3 · TIDYClean up the code. Every test still passes.

    What you see: first red: expected 40, got 0, then green: $40.00 matches.

    The agent commits and pushes the test before the code that makes it pass, so the commit history shows every test came first. It explains each test in plain English. It's never allowed to weaken or delete a test to make it pass. If a test looks wrong, it has to stop and ask you.

  5. 5
    Agent builds · you check

    Build the page and check it by hand

    When every rule is green, the agent builds the page and starts a web server so you can open it. Enter $50 with 20% off and confirm you get $40.00, try the other rules, then try a price from a real receipt of your own. Tests can pass while checking the wrong thing, and this check catches that.

  6. 6
    Agent · you describe your check

    Wrap up on the issue

    The agent asks how you checked the page, then posts a comment on issue #1 with the final test results, the commits in order, and your hand check. It ticks the rules you confirmed and closes the issue. The issue and the commit history are your record of how it went.

Things you can say to the agent

Starting an issue

Let's work on issue #1, following AGENTS.md.

Understanding a test

Explain in plain English what each test checks, and how it could still pass while the code is broken.

Checking the history

Show me the commits so far, in order, and point out where each test came before its code.

Signs the agent skipped a step

  • StopIt wrote code before you saw a red (failing) test run.
  • StopIt changed or deleted a test to make it pass, without asking you.
  • StopIt says "all tests pass" but didn't show you the output.
  • StopIt built things none of your examples asked for.

If you see any of these, say: "Stop. Go back and follow the test-first steps in AGENTS.md."
